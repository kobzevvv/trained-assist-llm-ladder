# Пул токенов провайдеров в админке (OpenRouter, OpenCode Go)

Админка Ladder (`https://llm-ladder.trainedassist.store/admin`) умеет показывать и
пополнять пул ключей провайдеров: вкладки **OpenRouter** и **OpenCode Go**. Ключ,
добавленный через веб-интерфейс, сразу попадает в пул — перезапуск воркера и
`wrangler secret put` не нужны.

## Как это устроено

| Слой | Что лежит | Кто это видит |
|---|---|---|
| Worker secrets | `OPENROUTER_API_KEY`, `OPENCODE_GO_API_KEYS` | только воркер; в админке — одна строка «Секрет воркера» |
| D1 `provider_credentials` | токены, зашифрованные AES-GCM | админка видит только маску (`sk-or-••••3456`) |
| `PROVIDER_CREDS_KEY` | 32 случайных байта, base64 — ключ шифрования | только воркер и GitHub secrets |

Пул собирается на каждый вызов: сначала секрет воркера, потом строки D1 по
`created_at`. Если `PROVIDER_CREDS_KEY` не задан или D1 недоступен, лестница
работает ровно как раньше — только на секрете воркера. Секрет остаётся
источником истины: без него админка откажется сохранять токен (503), а не
положит его в открытом виде.

## Добавление токена

1. Открыть `/admin`, подключить ключ администратора.
2. Вкладка **OpenRouter** или **OpenCode Go** → форма «Добавить токен».
3. Указать название (до 80 символов) и сам токен.

Форма отвергает заведомо нерабочие значения:

- ключ Go должен начинаться с `oc_sk_` (опечатка `os_sk_` валит все ранги Go —
  инцидент #86);
- ключ OpenRouter должен начинаться с `sk-or-`.

## Что происходит с токеном

- Значение шифруется AES-GCM (случайный 12-байтовый IV на значение) и кладётся в
  D1 как `base64(v1 || iv || ciphertext+tag)`. Префикс `v1` оставлен под будущую
  ротацию ключа.
- В листинге, в логах и в трассе значение не появляется: только маска
  (первые 6 символов + последние 4).
- «Отключить» переводит строку в `status = 'disabled'` — токен мгновенно уходит из
  пула, но строка остаётся для аудита.

## Ротация

- **Go** — пул с общей логикой: при отказе уровня ключа (401/429) лестница
  переключается на следующий ключ пула и на другой ранг, если пул исчерпан.
- **OpenRouter** — круговой курсор по пулу: вызовы чередуют ключи, поэтому
  лимит одного ключа не съедает весь платный хвост. При отказе уровня ключа
  (401/429) делается **одна** ротация на следующий токен в пределах вызова.
  `402 Insufficient credits` — ограничение аккаунта, а не ключа: ротация его не
  чинит, поэтому такой ответ ротацию не запускает.
- **У каждого ключа пула OpenRouter — свой аккаунт**, и дневной счётчик
  бесплатных запросов (`free_model_daily_requests`) считается **на аккаунт**:
  замерено 2026-10-22 — env-аккаунт 924/1000, четыре аккаунта из D1 — 12–57
  при лимите 50 (потолок аккаунта выбирается по купленным за всё время
  кредитам: < $10 — 50/сутки, ≥ $10 — 1000/сутки). Поэтому «лимит пула» —
  сумма по аккаунтам (`/v1/or-usage` → `accounts[]` + `pool`), а не счётчик
  одного ключа: один исчерпанный аккаунт — это не конец бесплатного хвоста,
  остальные аккаунты ещё живы (`docs/free-tier-limits.md`).
- **Замеры бесплатных моделей** тоже берут ключи из этого пула: у бесплатного
  тарифа OpenRouter лимит на аккаунт, поэтому бенчмарк ротирует ключи по пулу и
  не бьёт по одному (`docs/openrouter-fast-lane.md`).

## Секрет

`PROVIDER_CREDS_KEY` — 32 случайных байта в base64:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

Значение обязано быть **стабильным**: новый ключ сделает все сохранённые
токены нечитаемыми (в листинге они останутся, но пул их не расшифрует). В
проде значение лежит в GitHub secrets и публикуется в воркер на каждом деплое
(шаг «Publish provider credential key» в `.github/workflows/ci.yml`).

Локально — в `.dev.vars` (см. `.dev.vars.example`).
